# 계정 설정 API v1

- 상태는 구현 기준 확정이다. 메인이 계약을 정했으며 백엔드와 프런트 구현에 적용한다.
- 기존 계정 조회인 `GET /api/v1/user` 및 프로필과 공개 설정을 함께 저장하는 `PUT /api/v1/user`의 요청과 응답은 기존 클라이언트에서 그대로 사용할 수 있다.
- 아래 경로는 서버 기준이다. 프런트는 기존 API baseURL 및 프록시를 사용한다.
- 기존 JWT Bearer 인증을 사용한다. 설정은 인증 주체의 내부 계정 ID로 한정한다. 경로, 쿼리 또는 본문의 계정 식별자로 저장 대상을 선택할 수 없다.

| 메서드 및 경로 | 요청 JSON 예시 | 성공 |
| --- | --- | --- |
| `PATCH /api/v1/user/profile` | `{"userName":"이름","email":"name@example.com"}` | 204, 본문 없음 |
| `PATCH /api/v1/user/privacy` | `{"historyPrivate":"PUBLIC","personalPrivate":"PRIVATE"}` | 204, 본문 없음 |
| `PUT /api/v1/user/password` | `{"currentPassword":"OldPass!2","newPassword":"NewPass!3"}` | 204, 본문 없음 |

표의 필드는 모두 필수 문자열이다. 필드 누락, null, 빈 값은 허용하지 않는다. 이름과 이메일은 각각 최대 255자이며, 이메일 형식도 검증한다. 공개 상태는 대문자 `PUBLIC` 또는 `PRIVATE`다. 새 비밀번호에는 영문자, 숫자, 가입 시 허용하는 특수문자가 각각 하나 이상 있어야 하며 최소 8자와 최대 72 UTF-8 바이트를 적용한다. 현재 비밀번호는 기존 BCrypt 해시와 비교하며 새 비밀번호의 형식이나 바이트 한도를 적용하지 않는다. 앞뒤 공백도 입력값에 포함한다. 현재 비밀번호와 동일한 새 비밀번호는 사용할 수 없다.

| HTTP | 오류 코드 | 응답 처리 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 누락되거나 유효하지 않은 필드를 수정한다. |
| 401 | `PASSWORD_NOT_MATCH` | 현재 비밀번호를 확인한다. |
| 404 | `USER_NOT_FOUND` | 계정의 현재 상태를 확인한다. |
| 409 | `PASSWORD_CHANGED` | 현재 비밀번호를 다시 입력하고 변경을 재시도한다. |

오류 본문의 필드는 `code`와 `message`다. 인증 정보가 없는 요청은 기존 JWT 보안 정책을 적용한다. 비밀번호와 해시는 API 응답에 포함하지 않는다.

프로필과 공개 설정은 사용자 모듈의 해당 열만 각각 갱신한다. 기존 PUT은 네 메타데이터 열만 갱신한다. 비밀번호는 현재 해시가 비교 시점과 같을 때에만 새 BCrypt 해시로 갱신한다. 스키마 변경은 없다.

같은 프로필 또는 공개 설정 요청을 다시 보내면 같은 값을 저장한다. 비밀번호가 이미 바뀐 뒤 같은 본문을 재전송하면 이전 현재 비밀번호와 일치하지 않는다. 비밀번호 변경은 기존 JWT 세션을 유지한다.

DB 없는 검증은 MockMvc 인증 주체와 필드 검증, 기존 PUT 응답, 비밀번호 오류 응답 및 BCrypt를 쓰는 서비스 테스트를 포함한다. 실제 DB 및 브라우저 연동은 별도 검증 범위다.
