# API 계약 변경서

API 변경이 필요한 작업에만 복사해 사용한다. 실제 계약 문서는 백엔드 저장소의
`docs/contracts/<기능>.md`에 보관하고, 프런트 작업서에 경로·계약 버전·커밋을 기록한다.
상대 저장소가 없으면 필요한 계약 본문을 작업서에 전달한다.

- 상태: 초안 / 구현 기준 확정 / 검증 완료
- 계약 버전·작업 ID:
- 작성자: 메인 / 확인: backend, frontend
- 목적과 호환성: 기존 클라이언트 영향, 전환 필요 여부
- 메서드·경로: baseURL과 프록시 접두사는 별도로 기록
- 인증·소유권: 토큰, 본인/타인/공개 사용자 처리
- path/query/header: 이름, 타입, 필수 여부
- 요청 JSON: 정확한 camelCase/snake_case, 누락/null/빈 값 의미
- 성공 상태·응답 JSON: 객체/배열, 날짜 형식, 빈 응답·미존재 의미
- 실패: HTTP 상태, 오류 code, 사용자 동작
- 저장 영향: 모듈 데이터 소유권, 트랜잭션 범위, 파일 처리
- 재시도: 중복 요청 가능성, 멱등성, 결과 불명확 시 처리
- 검증 사례: 정상 / 잘못된 입력 / 미인증 / 타인 / 미존재 중 관련 사례
- 증거: 실제 수행한 API·테스트·브라우저 검증과 남은 공백

예시 JSON은 실제 DTO와 직렬화 설정을 확인해서 채운다. 타입스크립트 타입만으로 일치를 판단하지 않는다.
계약이 바뀌면 버전을 올리고 양쪽 담당에 같은 본문을 전달한다.
