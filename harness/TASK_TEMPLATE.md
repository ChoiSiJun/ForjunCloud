# 담당 에이전트 작업서

작업 규모에 맞춰 필요한 항목만 채운다. 전체 대화·전체 소스·장문의 로그를 복사하지 않는다.
메인이 구현 범위를 나누고, 각 구현 담당이 완료 조건과 검증 결과를 QA에 넘긴다.

- 작업 ID / 담당: backend 또는 frontend
- 목표: 사용자가 관찰할 변경 한두 문장
- 소유 경로: 담당이 수정할 저장소와 파일 범위
- 관련 파일·심볼: 시작점과 참고 예제
- 적용 지침·스킬: 이번 작업에 필요한 경로만 지정
- 확인한 사실: 메인이 이미 조사한 내용과 기존 사용자 변경
- 유지할 사항: 구조·스타일·호환성·변경하지 않을 계약
- API 계약: 해당하는 경우 계약 문서 경로와 버전
- 완료 조건: 성공·실패·권한·경계 조건 중 관련 항목
- 검증: 필요한 명령, 환경, 브라우저 확인 범위
- 의존성: 다른 담당 결과를 기다려야 하는 부분

## 반환 형식

- 변경 파일과 사용자 동작 변화
- API 계약 영향: 없음 또는 구체 변경
- 검증: 명령 / 종료 코드 / 확인한 범위
- 미해결: 코드 실패 / 환경 실패 / 미실행 구분
- 메인에게 필요한 결정이나 후속 작업

계약 변경이 발견되면 다른 담당이 추측으로 진행하지 않도록 메인에 즉시 전달한다.

## QA 작업서

- 요청 동작과 완료 조건
- 구현 담당이 보고한 변경 파일·심볼, 확정 계약 및 검사 결과
- 작업 시작 기준과 프런트·백엔드 코드 리뷰 범위
- 백엔드 변경 여부와 영향 범위 탐색 시작점
- 허용된 선택 검사와 별도 요청으로 실행할 통합 검증

요청 동작을 먼저 검사하고, 변경된 백엔드 코드의 호출자·공통 사용처를 추적해 영향받는 동작을 추가 검사한다.
프런트와 백엔드의 실제 변경분을 코드 리뷰하고 다음을 반환한다.

- 프런트·백엔드별 전체 변경 파일과 각 파일의 추가·수정·삭제 상태. 변경이 없는 영역도 표시한다.
- 리뷰 지적별 심각도, 파일과 줄, 발생 조건과 영향, 수정 후 재확인 결과. 지적이 없으면 검토 범위와 함께 표시한다.
- 요청 동작과 영향 동작별 검사 결과, 명령과 종료 코드, 미실행 범위.

회귀 수정은 메인이 구현 담당에게 다시 배정한다.
